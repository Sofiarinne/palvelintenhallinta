### Karvinen 2026: Sudo without password

-`sudo -i` avaa root-käyttäjän istunnon

-lisätään `sudo visudo /etc/sudoers.d/sudoless` tiedostoon rivi `%sudoless ALL = (ALL) NOPASSWD: ALL`, jotta sudoless-ryhmän
käyttäjät voivat tehdä sudo komentoja ilman salasanaa

-sudoers kansion pääte .d tarkoittaa, että ohjelma lukee ison asetustiedoston (sudoers) lisäksi myös tuon .d -päätteisen,
ja sinne voi lisätä omia muutoksia, jotta isoon asetustiedostoon ei tarvitse koskea ja mahdollisesti sotkea sitä

-ennen tiedoston muokkaamista on tarpeellista avata toinen terminaali sudo oikeuksilla taustalle (sudo -i), jotta jos jokin menee pieleen,
niin ei lukitse itseään kokonaan pois sudo oikeuksista vahingossa



#### -%sudoless ALL = (ALL) NOPASSWD: ALL avattuna:

-`%` tarkoittaa ryhmää, ilman sitä "sudoless" tulkittaisiin käyttäjänä

-`ALL` tarkoittaa kaikkia koneita

-`=` on erotinmerkki

-`(ALL)` tarkoittaa että komentoja saa komentaa minä käyttäjänä tahansa

-`NOPASSWD: ALL` poistaa salasanakyselyn ja ALL tarkoittaa mitä komentoja saa ajaa ilman salasanaa, eli kaikkia

-Kiteytettynä ryhmän sudoless jäsenet saavat millä tahansa koneella ajaa mitä tahansa komentoa kenenä tahansa käyttäjänä
ilman salasanaa


-`sudo -k` pakottaa unohtamaan sudo-oikeudet

### Karvinen 2026: Passwordless Sudo with Ansible:

-käyttäjän lisäämisen sudoless ryhmään voi automatisoida ansiblella

-main.yml tiedostoon on lisättävä neljä kohtaa: group, user, authorized_key ja copy

-site.yml tiedostoon on lisättävä rivi `become: true`, jotta ansible käyttää sudoa komennon ajaessa, koska esim. käyttäjien
ja ryhmien luominen vaatii sudo-oikeudet

-tämän jälkeen ajo kuitenkin epäonnistuu ensimmäisellä kerralla, koska ansible ei tiedä sudo-salasanaa. On kirjoitettava komento
`ansible-playbook site.yml --ask-become-password`

# a

Tämän tehtävän tarkoituksena oli tehdä ansiblea varten tunnus, jolla voi käyttää sudoa ilman salasanaa. Sekä ssh-kirjautuminen että sudon käyttö tulee olla ansbilea varten automatisoitu.

Ensiksi tein uuden käyttäjän, uuden ryhmän sekä lisäsin käyttäjän ryhmään.

    sudo adduser sofku
    sudo groupadd sudoless
    sudo adduser sofku sudoless

Sitten avasin kaksi terminaali ikkunaa, toinen root oikeuksilla, sillä jos vahingossa sotkisin jotakin ja estäisin pääsyni root
oikeuksilla, voisin palata vielä toisesta ikkunasta korjaamaan virheet.

Palasin toiseen terminaaliin (ei root) ja loin tiedoston /etc/sudoers.d/sudoless

    sudo visudo /etc/sudoers.d/sudoless

Visudo on tekstieditori, jolla muokataan sudon asetustiedostoa. Sen hyöty on siinä, että se tarkistaa tiedoston syntaksin tallennettaessa ja varoittaa, jos siinä on virhe. Silloin sen voi korjata ennen kuin vahinko on tapahtunut. (clauden koulutusdata). Eli perus tekstieditorilla esim. nanolla tai vimillä ei kannata koskea sudon asetustiedostoon! Pahimmassa tapauksessa se voi lukita sinut ulos omasta järjestelmästäsi, jos tiedostoon tulee kirjoitusvirhe.

sudoers kansion pääte .d tarkoittaa, että ohjelma lukee ison asetustiedoston (sudoers) lisäksi myös tuon .d -päätteisen,
ja sinne voi lisätä omia muutoksia, jotta isoon asetustiedostoon ei tarvitse koskea, mikä mahdollisesti voisi sotkea sen. Sinne
voi lisätä turvallisesti omia muokkauksia.

Ja lisäsin sinne rivin

    %sudoless ALL = (ALL) NOPASSWD: ALL

-`%` tarkoittaa ryhmää, ilman sitä "sudoless" tulkittaisiin käyttäjänä

-`ALL` tarkoittaa kaikkia koneita

-`=` on erotinmerkki

-`(ALL)` tarkoittaa että komentoja saa komentaa minä käyttäjänä tahansa

-`NOPASSWD: ALL` poistaa salasanakyselyn ja ALL tarkoittaa mitä komentoja saa ajaa ilman salasanaa, eli kaikkia

-Kiteytettynä ryhmän sudoless jäsenet saavat millä tahansa koneella ajaa mitä tahansa komentoa kenenä tahansa käyttäjänä
ilman salasanaa

#### Sitten vielä testasin että toimiko muutos, eli pääsenkö sofku käyttäjällä käyttämään sudo komentoja ilman salasanaa.

 Kirjauduin ssh:lla sofku käyttäjälle. `ssh sofku@localhost`.

Sitten tein `sudo -k`, mikä pakottaa koneen unohtamaan sudo oikeudet. Koska kone voi muistaa sudo oikeudet vielä noin 10 minuuttia sen jälkeen, kun salasana on syötetty. Käskin sudo oikeudet unohdettavaksi, jotta testi olisi oikeelllinen.

Kokeilin 

    $ sudo echo "moi"
    $ moi

sain vastaukseksi echon, eli moi, joten sudo ilman salasanaa toimi.

# b

Ensin loin uuden roolin "sofku" ja sille polun `roles/sofku/tasks/main.yml`.
Main.yml -tiedostoon tein seuraavanlaiset asetukset:

    - group:
        name: "sudoless"
        state: present
    - user:
        name: "sofku"
        state: present
        groups: ["sudoless", "sudo", "adm"]
    - authorized_key:
        user: "sofku"
        key: julkinen avain
    - copy:
        dest: "/etc/sudoers.d/sudoless"
        content: "%sudoless ALL = (ALL) NOPASSWD: ALL"
        owner: root
        group: root
        mode: "0644"

Lisäsin site.yml -tiedostoon roolin sofku sekä rivin `become: true`. Tämä sen takia, että ansible voi suorittaa tehtäviä, joihin tarvitaan root oikeuksia. Esim. roolissa käyttäjän ja ryhmän luonti sekä sudon asetustiedoston muokkaaminen vaativat sudo-oikeuksia.

    - hosts: all
      become: true
      roles:
        - hello
        - sofku

Sitten komensin `ansible-playbook site.yml` ja se valitti, että sudo tarvitsee salasanan.

    ansible-playbook site.yml -K

Näin pääsin syöttämään salasanan jonka jälkeen komento toimi. Teron ohjeen `--ask-become-password` ei toiminut, mutta `-K` tekee saman.
